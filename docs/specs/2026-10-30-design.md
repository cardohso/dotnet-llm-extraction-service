# Design: dotnet-llm-extraction-service

Date: 2026-10-30 · Status: approved 2026-10-30 and implemented; deviations are recorded in the README and eval/THRESHOLDS.md · Author: João Pedro Cardoso

## 1. Purpose

A small, production-style ASP.NET Core service that wraps an LLM for two document tasks:
structured extraction into a validated schema, and grounded summarisation. It exists to show
.NET backend design, LLM integration, structured output, testing, evaluation and CI.

Success means: CI green, tests pass offline, a real-provider evaluation with recorded results,
a fresh clone runs from the README alone, and a clean secret scan before the first push.

## 2. Decisions

| Topic | Decision |
|---|---|
| Framework | `net10.0` (current LTS). .NET 8 ends support 2026-11-10. |
| OpenAPI | Built-in `Microsoft.AspNetCore.OpenApi`. Swagger UI in Development only; `/openapi/v1.json` always served. |
| Default provider | Groq, `openai/gpt-oss-20b`, strict `json_schema` response format. |
| Alternative provider | Gemini OpenAI-compatible endpoint, by config only. |
| Auth | None. Listed as a limitation; rate limiting protects the free quota. |
| Repo | `dotnet-llm-extraction-service`, MIT licence, public after review. |
| Schema validation | Strict typed deserialisation plus semantic validators. No JSON Schema library. |
| Logging | Built-in `ILogger`, JSON console formatter, source-generated `LoggerMessage`. |

## 4. API

### `POST /extract`

Request:
```json
{ "schema": "incident-report", "text": "On 3 March 2026 at Entroncamento depot..." }
```
Response `200`:
```json
{
  "schema": "incident-report",
  "data": {
    "date": "2026-03-03",
    "location": "Entroncamento depot",
    "equipment": ["points machine P12"],
    "severity": "medium",
    "summary": "Points failure delayed two services; no injuries."
  },
  "attempts": 1,
  "usage": { "inputTokens": 412, "outputTokens": 96, "estimatedCostUsd": 0.0 }
}
```

### `POST /summarise`

Request: `{ "text": "...", "maxSentences": 3 }` (`maxSentences` 1–10, default 3).

Response `200`:
```json
{
  "summary": "...",
  "sources": [ { "index": 2, "text": "Exact sentence from the input." } ],
  "attempts": 1,
  "usage": { "inputTokens": 0, "outputTokens": 0, "estimatedCostUsd": 0.0 }
}
```

Grounding: the server splits input into numbered sentences (`SentenceSplitter`, regex on
`.!?` followed by whitespace, with a short abbreviation list; max 200 sentences). The model
returns `{ summary, sourceIndices[] }` under a JSON schema. The server rejects out-of-range or
empty indices (triggers the repair retry) and returns the original sentence text, so sources
are always verbatim.

### Health

- `GET /health/live` — process is running. No dependencies.
- `GET /health/ready` — options valid and provider circuit not open. Never calls the LLM.

## 5. Provider abstraction

```csharp
public interface ILlmClient
{
    Task<LlmResult> CompleteAsync(LlmRequest request, CancellationToken cancellationToken);
}

public sealed record LlmRequest(
    string SystemPrompt,
    string UserPrompt,
    LlmJsonSchema? ResponseSchema,   // name + JSON schema (JsonNode); null = free text
    int MaxOutputTokens,
    double Temperature = 0);

public sealed record LlmResult(string Content, LlmUsage Usage, string Model, string FinishReason);
public sealed record LlmUsage(int InputTokens, int OutputTokens);
```

Implementations:
- `OpenAiCompatibleLlmClient` — typed `HttpClient` via `IHttpClientFactory`, calls
  `{BaseUrl}/chat/completions`, sends `response_format: { type: "json_schema", json_schema: { name, strict: true, schema } }`
  and optional `reasoning_effort` (gpt-oss reasoning tokens count toward output). Maps HTTP
  failures to typed exceptions (`LlmRateLimitedException`, `LlmUnavailableException`, `LlmTimeoutException`).
- `FakeLlmClient` — deterministic. Plays a scripted queue of responses or exceptions; records
  every request for assertions. Used by all tests and the CI eval smoke run.

Options (`LlmOptions`, section `Llm`, `ValidateDataAnnotations().ValidateOnStart()`):
`Provider` (`OpenAiCompatible` | `Fake`), `BaseUrl`, `Model`, `ApiKey`, `ReasoningEffort`,
`InputPricePerMillionUsd`, `OutputPricePerMillionUsd`.
`ApiKey` comes only from user-secrets or the `Llm__ApiKey` environment variable.

## 6. Extraction schema: `incident-report`

| Field | Type | Rule |
|---|---|---|
| `date` | ISO date string or null | parses as `DateOnly`; not after today (UTC) |
| `location` | string or null | 1–200 chars when present |
| `equipment` | string[] | 0–20 items, each 1–100 chars, no duplicates |
| `severity` | enum | `low`, `medium`, `high`, `critical`, `unknown` |
| `summary` | string | 1–300 chars |

Null or `unknown` means "not stated". The prompt tells the model never to infer missing values.

Schemas implement `IExtractionSchema { Name, JsonSchema, Type, Validate(object) }` and are
registered in an `ExtractionSchemaRegistry`. The JSON schema is hand-written next to its C#
record; a unit test checks that their property names and required fields match.

Validation layers:
1. `JsonSerializer.Deserialize` with `UnmappedMemberHandling.Disallow` and strict enum handling.
2. Semantic validator returning a list of field errors.

## 7. Error, retry and budget policy

### Transport (`Microsoft.Extensions.Http.Resilience`)
- Total timeout 30 s; per-attempt timeout 10 s.
- Retry: 2 attempts, exponential backoff with jitter, on 408/429/5xx and timeouts; honours `Retry-After`.
- Circuit breaker: failure ratio 0.5, sampling 30 s, minimum throughput 5, break 30 s.

### Invalid model output
- Attempt 1 fails to parse or validate → one repair attempt: same prompt plus the previous output
  and the list of validation errors.
- Repair fails → `422`. No further attempts.

### Token and cost cap
- Input over 20,000 chars → `413` before any LLM call.
- `MaxOutputTokens`: extract 800, summarise 600.
- Per-request budget 16,000 tokens across attempts (sized so a maximum-length input still
  fits one repair: about 5,800 tokens for attempt 1 plus about 6,600 for the repair). Input is estimated as chars / 4 before the call; real usage
  from the response is used after. If attempt 1 leaves less than the next attempt's estimate,
  skip the repair and return `422` with reason `budget-exhausted`.
- Estimated cost = usage × configured prices; logged and returned. Free tier prices default to 0.

### Error responses (all `ProblemDetails`, `traceId` included)

| Status | When | `type` suffix |
|---|---|---|
| 400 | invalid request body, unknown schema | `validation` |
| 413 | input too long | `input-too-large` |
| 422 | model output invalid after repair, or budget exhausted | `llm-output-invalid` |
| 429 | our rate limiter rejected the request (`Retry-After` set) | `rate-limited` |
| 502 | provider returned an error after retries | `provider-error` |
| 503 | circuit open | `provider-unavailable` |
| 504 | provider timeout | `provider-timeout` |

Client cancellation: the request's `CancellationToken` flows to the HTTP call; cancelled requests
are logged at Information and not counted as provider failures.

### Rate limiting
- Per-IP token bucket: 20 requests per minute, burst 5.
- Global concurrency limiter on LLM endpoints: 4 in flight, queue 10.
- Values configurable in `RateLimiting` section.

### Logging
Structured JSON. Each LLM call logs schema/task, attempt, model, input/output tokens, latency,
outcome and estimated cost. Input text is never logged; only its length and a SHA-256 prefix.

## 8. Evaluation

- `eval/golden/incident-reports.jsonl`: 18 synthetic rail incident texts written for this repo, with
  expected fields. Coverage: all five severities, missing date, missing location, several pieces of
  equipment, relative dates ("yesterday") that must stay null, and 3 Portuguese texts.
  Reviewed with João before use.
- Scoring per field:
  - `date`, `severity`: exact match (null = null counts as correct).
  - `location`: case- and whitespace-normalised exact match.
  - `equipment`: set F1 after normalisation.
  - `summary`: not scored for content; must pass validation.
- Metrics: per-field accuracy, overall field accuracy (mean of date, location, equipment F1,
  severity), first-attempt valid rate, valid rate after repair, p50/p95 latency, total tokens.
- Thresholds (in `eval/THRESHOLDS.md`, committed before the first real run):
  valid after repair ≥ 95 %, overall field accuracy ≥ 85 %, severity ≥ 80 %, p95 latency ≤ 5 s.
- Run: `dotnet run --project eval/DocService.Eval -- --provider groq`. Writes
  `eval/results/<date>.json` and `.md`. Exit code 1 if any threshold is missed.
- CI runs the harness against `FakeLlmClient` as a smoke test so it can't rot.

## 9. Testing

Core (xUnit, `FakeLlmClient`):
- valid first attempt; invalid then valid (repair prompt contains errors); invalid twice → failure
- budget exhausted skips repair
- each semantic validator rule
- sentence splitter cases; summary index validation
- JSON schema ↔ record consistency

API (`WebApplicationFactory`, fake client swapped in):
- happy paths for both endpoints
- each ProblemDetails status above, including 429 from the limiter and 413
- health endpoints
- OpenAPI document is served

Provider client (stub `HttpMessageHandler`):
- request body shape (`response_format`, `max_tokens`, auth header)
- usage parsing; error status mapping

No test touches the network.

## 10. Delivery

- **Dockerfile:** multi-stage (`sdk:10.0` → `aspnet:10.0`), runs as the built-in non-root `app` user, `HEALTHCHECK`
  on `/health/live`.
- **`ci.yml`** (push, pull_request): restore, `dotnet format --verify-no-changes`, build `-warnaserror`,
  test, eval smoke run against the fake. Status badge in README.
- **`eval.yml`** (`workflow_dispatch` only): real Groq run using the `GROQ_API_KEY` repository secret;
  uploads results as an artifact.
- **Secrets:** user-secrets locally, `.env.example` committed, `.env` git-ignored. Secret scan
  (gitleaks) before the first push.

## 11. Out of scope

Authentication, persistence, streaming responses, multiple schemas beyond `incident-report`,
PDF/OCR input, multi-tenant quotas, deployment to a cloud host.

## 12. Known limitations (for README)

- Synthetic golden set of 18 items; results show the method, not production accuracy.
- Regex sentence splitter; unusual punctuation may split badly.
- Token estimate before the call is approximate (chars / 4).
- Free-tier rate limits cap throughput; latency depends on Groq load.
- No auth; not for public deployment as-is.
